# Internacionalización y selector compartido

## Catálogos

`src/i18n/locales/{idioma}/{seccion}.json` contiene únicamente textos traducibles. Cada idioma conserva las mismas claves y parámetros:

| Sección | Contenido |
| --- | --- |
| `common` | Accesibilidad general, idioma, selector y título del documento |
| `time` | Reloj, fecha UTC y validación |
| `location` | Ubicación, permisos, campos y avisos |
| `search` | Preparación, resultados y estados de carga |
| `sky` | Aspecto del cielo, estrellas y puntos cardinales |
| `errors` | Fallos de red, API, imágenes y proyección |

Las claves describen su propósito, por ejemplo `search.fields.ra.help`. Los nombres de archivos y claves son ASCII; los textos visibles mantienen su ortografía. No utilizar frases como claves ni construir oraciones concatenando fragmentos traducidos.

## Uso

- `I18nProvider`, en `src/i18n/`, utiliza Context de **React** para compartir el idioma. Conserva la elección en `localStorage`, actualiza `html.lang` y traduce el título del documento. El idioma predeterminado es inglés, independientemente del idioma del navegador; una preferencia válida guardada en `astrea.language` tiene prioridad. Inglés también es el idioma de respaldo para traducciones ausentes. Si el almacenamiento está bloqueado, el selector sigue funcionando en memoria.
- `useTranslation()` es el hook local que devuelve `t`, `language`, `setLanguage`, `number` y `date`.
- `t('time.actions.pause')` obtiene un texto. `t('search.notices.found', { count: 2 })` selecciona el plural. Los catálogos interpolan parámetros mediante `{{count}}`; las formas `one`, `other` y las adicionales de cada idioma se resuelven con **Intl.PluralRules**.
- `number(value, options)` utiliza **Intl.NumberFormat**. `date(value, options)` utiliza **Intl.DateTimeFormat**. La hora del HUD permanece local; las observaciones se presentan explícitamente en UTC. No se traducen identificadores de observaciones, nombres de colecciones ni unidades científicas provenientes de los datos.
- Los hooks y servicios guardan claves o descriptores `{ key, values }`, nunca frases ya traducidas. `t(descriptor)` resuelve también parámetros que contengan otros descriptores. Así, una operación iniciada en español puede finalizar en inglés y un error visible cambia de idioma inmediatamente, sin repetir consultas ni reiniciar tareas.
- `LocalizedError` y `errorMessage`, de `i18n/messages.js`, transportan errores traducibles. `apiMessages.js` relaciona las respuestas estables de la API actual con claves. Los detalles desconocidos conservan su diagnóstico en el error y presentan un mensaje traducido por estado HTTP. Cuando la API incorpore códigos de error, deben sustituir este mapa de mensajes.

La capa i18n usa **React** y las API nativas **Intl** y **localStorage**. No requiere instalar dependencias adicionales. Los textos se renderizan como contenido de React, sin interpretar HTML.

## Añadir textos o idiomas

1. Añadir la clave semántica en la sección correspondiente de ambos idiomas, con los mismos parámetros.
2. Consumirla con `t` en la presentación; conservar la clave en estados, validaciones y operaciones asíncronas.
3. Para una sección nueva, crear su JSON en cada idioma y registrarlo en `resources.js`.
4. Para otro idioma, copiar la estructura de catálogos, traducirla y registrarla en `resources` y `languages` de `resources.js`. Cada entrada declara `value`, nombre nativo `label`, abreviatura `shortLabel` y atributo `lang`. El menú se genera desde ese registro.
5. Revisar plurales, parámetros, ayudas, textos accesibles y mensajes de error. `tests/i18n.test.mjs` comprueba la paridad de claves y parámetros, los plurales, la selección inicial y la retraducción de errores.

## Select reutilizable

`components/common/Select.jsx` implementa un selector controlado. `LanguageSelect.jsx` lo integra abajo a la izquierda con el icono `GlobalLine` y el código del idioma.

### Integración en otros controles

1. Importar `Select` desde `components/common/Select.jsx` y utilizarlo dentro de `I18nProvider`.
2. Conservar el valor seleccionado en el componente padre, por ejemplo con `useState` de React. Pasarlo mediante `value` y actualizarlo desde `onChange`, que recibe el valor de la opción, no un evento del navegador.
3. Preparar `options` con valores estables y etiquetas obtenidas de los catálogos mediante `t`. `shortLabel` permite abreviar el disparador sin acortar las opciones de la lista.
4. Proporcionar `label` como nombre accesible. El componente no dibuja una etiqueta externa; el formulario debe mostrarla cuando su contexto lo requiera. `ariaLabel` permite ampliar la descripción del disparador.
5. Añadir `name` cuando el valor deba formar parte de `FormData`. La selección sigue siendo controlada por el padre; cualquier restablecimiento del formulario debe actualizar también ese estado.
6. Usar `placement="auto"` y declarar obstáculos mediante `avoidSelector` cuando proceda. `boundaryRef` permite limitar el desplegable a una región visible adicional. Los elementos que contienen el disparador no se consideran obstáculos.

Las dependencias son **React**, **react-dom**, el hook local `useTranslation` y las API de medición del navegador. Los estilos ya se importan desde `styles/main.css`; no es necesario duplicarlos en el componente consumidor.

### Propiedades

| Propiedad | Propósito |
| --- | --- |
| `value`, `onChange` | Valor actual y callback que recibe el nuevo valor |
| `options` | Opciones con `value` de texto único y no vacío, `label`, y opcionalmente `shortLabel`, `lang`, `disabled` |
| `label`, `ariaLabel` | Nombre accesible de la lista y, opcionalmente, del disparador |
| `id`, `name` | Identificador y nombre opcional para incluir el valor en formularios mediante un select nativo oculto |
| `icon`, `placeholder`, `disabled`, `className` | Presentación del disparador y disponibilidad |
| `placement` | `auto` por defecto; admite preferencia `top` o `bottom`, con inversión si falta espacio |
| `avoidSelector` | Selector CSS de elementos que conviene evitar; el HUD utiliza `data-select-obstacle` |
| `boundaryRef` | Límite opcional adicional al área visible de la ventana |

El foco permanece en el disparador con semántica `combobox`, `listbox`, `option` y `aria-activedescendant`. Las flechas recorren opciones habilitadas; Inicio y Fin van a los extremos; escribir busca por nombre; Enter o Espacio confirman; Escape, Tab y clic externo cierran. Las opciones seleccionadas muestran una marca además del color. El cierre conserva la transición visual y desactiva la lista mediante `inert`.

`useSelectPosition`, de `src/hooks/`, mide el disparador y la lista con API del navegador (`getBoundingClientRect`, `ResizeObserver`, `MutationObserver`, `visualViewport` y `requestAnimationFrame`). `selectPosition` calcula el lado, desplazamiento horizontal y altura disponible. Evita los controles cercanos si hay espacio; si ambos lados quedan obstruidos, prioriza una lista utilizable superpuesta. Las listas largas tienen scroll. La posición se actualiza al cambiar tamaño, contenido, scroll o visibilidad de los obstáculos.

El portal procede de **react-dom** y evita recortes por el scroll del panel. `styles/components/select.css`, importado desde `main.css`, aplica las variables compartidas del HUD, foco visible, movimiento reducido y animaciones de entrada y salida. No se añaden bibliotecas de posicionamiento.

## Comprobación manual

Con la aplicación abierta y sin una preferencia guardada, comprobar que el idioma inicial sea EN, también con un navegador configurado en español. Comprobar ES/EN en cada panel, ayudas, avisos pendientes, puntos cardinales y fechas; recargar para verificar la preferencia. Probar el selector con teclado y pantalla estrecha o baja, y una lista extensa con opciones deshabilitadas al reutilizarlo. Las pruebas unitarias de geometría no sustituyen esta comprobación visual.
